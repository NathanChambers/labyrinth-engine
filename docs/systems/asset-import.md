# Asset import

**Status:** Implemented for static FBX meshes and metallic-roughness PBR images\
**Owner:** `crates/asset_import`  
**Source:** [FBX conversion](../../crates/asset_import/src/lib.rs), [mesh and texture contract](../../crates/mesh/src/lib.rs)

## Purpose and boundary

Asset import converts static FBX files into CPU `Mesh`, `Material`, `Texture`, and `Transform` values. It does not own files, scene entities, GPU resources, or rendering state. The `fx` example uses the importer to build a small self-contained Featherweight environment scene from copied assets.

## State and invariants

The importer has no persistent state. Each load creates validated mesh geometry, and copies decoded texture pixels into shared CPU texture data. Imported materials preserve base color, scalar metallic and roughness values, and optional base-color, tangent-space normal, metallic, and roughness images. FBX coordinates are converted to right-handed Y-up meters. Model transforms are returned with imported mesh parts for the application to assign when creating scene instances.

## Public contract

`load_fbx` resolves textures beside the model. `load_fbx_with_texture_roots` also searches caller-provided asset folders by path and filename, ignoring filename case and Unity-style duplicate suffixes such as ` (1)`. When FBX omits a PBR map reference, the importer also checks for conventional sibling names derived from the base-color map, including shared `_Red`, `_Green`, and `_Blue` material variants. Supported image inputs are PNG and PSD. Each material part becomes one `ImportedMesh`; the importer preserves UV seams by emitting a vertex per triangle corner and uses ufbx triangulation for polygon faces. Missing normals are generated by ufbx; absent UVs and vertex colors receive neutral defaults.

The importer handles static triangle meshes and the metallic-roughness PBR maps consumed by `Material`. It ignores animation, skinning, blend shapes, custom shader graphs, and alpha blending/cutout behavior. Missing explicitly referenced images, malformed meshes, and unsupported image data return an error unless the caller opts into missing-texture fallback.

## Lifecycle

The application calls the importer during scene setup, receives owned CPU values, and transfers cloned mesh/material values into `Scene`. Cloned meshes share geometry and cloned textures share pixel storage. The renderer creates GPU resources when it receives scene instances. There is no reload or background-loading path yet.

## Connections

## Verification and open questions

`cargo check --offline -p mesh -p asset_import -p renderer -p sponza` compiles the importer and four-channel renderer path. Runtime loading and visual output of the Sponza PBR maps have not been exercised in this session. Alpha-tested cutout support and additional PBR texture channels remain open work.
