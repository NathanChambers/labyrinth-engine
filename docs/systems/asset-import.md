# Asset import

**Status:** Implemented for static FBX meshes and base-color images  
**Owner:** `crates/asset_import`  
**Source:** [FBX conversion](../../crates/asset_import/src/lib.rs), [mesh and texture contract](../../crates/mesh/src/lib.rs)

## Purpose and boundary

Asset import converts static FBX files into CPU `Mesh`, `Material`, `Texture`, and `Transform` values. It does not own files, scene entities, GPU resources, or rendering state. The `fx` example uses the importer to build a small self-contained Featherweight environment scene from copied assets.

## State and invariants

The importer has no persistent state. Each load creates validated mesh geometry, and copies decoded texture pixels into shared CPU texture data. Imported materials preserve base color, scalar metallic and roughness values, and an optional base-color image. FBX coordinates are converted to right-handed Y-up meters. Model transforms are returned with imported mesh parts for the application to assign when creating scene instances.

## Public contract

`load_fbx` resolves textures beside the model. `load_fbx_with_texture_roots` also searches caller-provided asset folders by path and filename, ignoring filename case and Unity-style duplicate suffixes such as ` (1)`. Supported image inputs are PNG and PSD. Each material part becomes one `ImportedMesh`; the importer preserves UV seams by emitting a vertex per triangle corner and uses ufbx triangulation for polygon faces. Missing normals are generated by ufbx; absent UVs and vertex colors receive neutral defaults.

This first slice handles static triangle meshes and base-color textures. It ignores animation, skinning, blend shapes, normal maps, metallic/roughness images, custom shader graphs, and alpha blending/cutout behavior. Missing referenced images, malformed meshes, and unsupported image data return an error.

## Lifecycle

The application calls the importer during scene setup, receives owned CPU values, and transfers cloned mesh/material values into `Scene`. Cloned meshes share geometry and cloned textures share pixel storage. The renderer creates GPU resources when it receives scene instances. There is no reload or background-loading path yet.

## Connections

| Other system | Direction | Data or command | When | Failure behavior |
| --- | --- | --- | --- | --- |
| [Mesh](mesh.md) | Asset import → mesh | Validated indexed geometry, UVs, scalar PBR values, and decoded RGBA8 base-color texture pixels | Model load | Conversion or image errors are returned to the caller |
| [Rendering](rendering.md) | Asset import → rendering through mesh | Imported mesh and texture values retained by scene instances | Renderer initialization | Invalid mesh/image values are rejected before upload |
| [FX example](../../examples/fx/src/main.rs) | FX example → asset import | Copied static terrain, building, prop FBX files, and texture search root | Scene setup | Startup returns the import error |

## Verification and open questions

`cargo check --offline --workspace` compiles the importer and the example consumer. Runtime loading and visual output of the copied assets have not been exercised in this session. Alpha-tested cutout support and additional PBR texture channels remain open work.
