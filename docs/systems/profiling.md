# Profiling

The renderer exposes CPU phase timings through `RendererPerformanceStats`. The debug panel displays overall frame CPU time, light and instance updates, probe updates, SDF update scheduling and enqueue times, rebuilt SDF voxel count, radiance-field availability, and the latest reported GPU timings. The GI radiance inspector can request a one-shot scene-pass GPU timing sample to inspect whole-scene GPU time. `frame_cpu_ms` measures the engine-side redraw path through submission; it does not include asynchronous GPU completion or display presentation time. When the adapter supports timestamp queries, reports include separate GPU timings for shadow, scene, world-space radiance-field update, dirty-region SDF compute, gizmo, and UI passes plus their total.

Rhai capture scripts can write a report beside screenshots:

```rhai
capture.wait(1.0);
capture.report("performance");
```

Reports are text files containing the measured CPU phases for the frame after the action is processed. The open-world capture script uses this path automatically. `examples/lighting/scripts/performance_matrix.rhai` applies four render-effect combinations and writes one report for each, making it possible to compare an unlit baseline with shadows and GI independently.

`examples/genos/scripts/performance.rhai` reports the full scene, gizmos disabled, GI disabled, and GI plus shadows disabled. Run it with `cargo run --release -p genos -- --scale big --capture-script=examples/genos/scripts/performance.rhai` to compare the large stress scene; use `--dynamic 0 --boxes-still --sun-speed 0` to isolate static-scene and lighting cost. `examples/genos/scripts/triangle_probe_occlusion_profile.rhai` emits enabled and disabled diagnostic reports, then takes five timing reports for each filter state while keeping the 4×4 scene static. Run it with `cargo run --release -p genos -- --scale big --dynamic 0 --boxes-still --sun-speed 0 --capture-script=examples/genos/scripts/triangle_probe_occlusion_profile.rhai`. The enabled report counts segment queries, BVH bounds tests, triangle tests, hits, BVH build time, and tree sizes; the disabled report confirms no queries execute. Atomic counters are disabled for the timing reports. Reports are written to `captures/genos-triangle-occlusion-profile/`.

GPU work is grouped with wgpu debug markers for RenderDoc captures. The primary groups are directional and spot shadow passes, world-space radiance-field compute, scene shading, gizmos, and UI. Timestamp results are resolved every frame and normally read back only for a scripted performance report. The shared GI inspector also provides an explicit one-shot timing sample; this blocks for the timestamp readback only when requested. Its `gpu_scene_ms` value covers the entire scene pass, so it reports whole-scene cost rather than the cost of a specific GI filter. SDF reports include CPU dirty-region scheduling time, GPU dirty-region voxel and clearance compute time, upload preparation/enqueue time, and rebuilt voxel count. Triangle-BVH reports include CPU build and transform-refit time plus tree sizes; opt-in traversal diagnostics count the segments, bounds tests, triangle tests, and hits for the last rendered frame. `examples/genos/scripts/triangle_probe_bvh_builder_ab.rhai` switches between median and binned SAH builders in a median/SAH/median sequence and writes five timing samples per phase, allowing within-run comparison and a check for timing drift. Run it without `--boxes-still` to profile transform refitting on Genos's moving boxes. A one-cell SDF scroll should report one exposed slab's voxel count; geometry changes or shifts at least as large as the SDF report a full rebuild. Adapters without timestamp support continue to report zero GPU timings.

Authored volumes and irradiance clipmaps evaluate probe refreshes on the CPU with a bounded per-frame budget. Their indirect lookup is evaluated per mesh vertex and interpolated across triangles. Experimental AABB-SDF mode instead updates one scene-sized world-space radiance field in a compute pass, then samples it per fragment. The configured cell counts were doubled on each axis, halving cell spacing for the same field extent; Receiver-to-probe visibility filtering has been removed; invalid relocation records are still excluded.

`examples/control` starts with no scene meshes, cameras, or lights. It shows a compact FPS label in the top-left by default; the displayed value updates every half-second. Pass `--no-fps` to disable the UI for a clean baseline. The renderer clears and presents the blank surface without scene passes. Run `cargo run -p control -- --profile-seconds=12` and `cargo run --release -p control -- --profile-seconds=12` to compare debug and release frame intervals and engine CPU frame time after a two-second warmup; add `--no-fps` to either command to disable the overlay. The report includes mean, standard deviation, p50, p95, p99, and maximum. Frame interval captures the event-loop/presentation cadence; engine CPU frame time ends at submission and does not include asynchronous GPU completion or display presentation. Timestamp readback is omitted so the measurement does not add a blocking GPU sync.

`examples/primitives` accepts the same `--profile-seconds=N` option. It profiles the animated cube, sphere, directional light, shared render debug panels, and the GPU scene; it reports frame-interval and engine CPU statistics after a two-second warmup.
