# Rendering

**Status:** Implemented  
**Owner:** `crates/renderer`  
**Source:** [Renderer](../../crates/renderer/src/lib.rs), [mesh contract](../../crates/mesh/src/lib.rs), [diffuse shader](../../crates/renderer/src/shader.wgsl)

## Purpose and boundary

Rendering turns a list of mesh instances into a perspective image on a supplied window. It owns GPU device, surface, pipeline, buffers, depth target, camera uniform, and presentation. [Windowing](windowing.md) owns the window lifecycle and calls the renderer at event boundaries. Mesh creation belongs to producers such as the engine primitive module or future asset importers.

## State and invariants

Each `MeshInstance` stores a mesh, a `Transform`, and a constant metallic-roughness `Material`. `Renderer` validates the supplied instances, applies transforms to positions and normals, flattens them with per-instance index offsets, and uploads geometry plus material values during initialization. `update_instances` rewrites transformed vertices and material values when instance topology is unchanged. The assigned `Camera` supplies view, projection, clear-color, and camera-position state; assigned directional lights supply the diffuse and specular lighting array. `update_camera` and `update_lights` write those changes to the uniform and render target. The surface configuration, depth target, and camera aspect match the most recent nonzero window size. The renderer supports one graphics API per instance through `GraphicsApi`; Vulkan is the default. Window mode changes do not change the renderer's API.

The current primitives example contains a white plane, red cube, and green UV sphere generated by the engine primitives module. The separate lighting example adds a room shell, doorway, exterior floor, and enabled irradiance volumes with debug bounds and probe markers. Its `--large-scene` mode adds connected rooms, an exterior colonnade, static props, emissive panels, a warm point light, a focused spot light, and a larger probe layout. Its `--open-world` mode creates a 128×128 terrain with 289 repeated structures, secondary props, emissive landmarks, and a sparse 576-probe volume for performance testing. Its `--gi-test` mode creates a neutral chamber with isolated colored objects and controlled local lights for image-based GI checks. The cube rotates and the sphere moves between two points using the math interpolation helpers. A right-handed perspective camera looks toward them. The WGSL shader combines a low base ambient term with assigned directional, point, and spot lights, directional and spot shadow maps, and nearest-probe indirect irradiance evaluated per vertex and interpolated across each triangle. Depth testing and back-face culling preserve the solid shapes. Rendering is split into explicit directional-shadow, spot-shadow, scene, irradiance-debug, and UI pass methods.

## Public contract

Renderer::capture renders the current scene to an independent target, reads back RGBA8 pixels at a requested resolution, and restores the visible camera uniform. The debug capture coordinator encodes those pixels as PNG output.

`Renderer::new` accepts a nonempty slice of `MeshInstance` values and a window surface supported by the selected graphics API. `update_instances` accepts changed transforms and materials while preserving vertex and index counts. `update_lights` updates directional, point, and spot light uniforms plus the directional and spot shadow transforms. Point and spot lights use range attenuation; spot lights also use inner and outer cone angles. Directional shadows use an orthographic map fitted to the initial world-space geometry bounds, while the first spot light uses a perspective shadow map. Point lights currently remain direct-only until a cubemap shadow path is added. `update_render_debug_mode` selects lit materials, unlit materials, or a wireframe edge pass. `RenderSettings` independently enables directional/spot shadow sampling and irradiance sampling; disabling irradiance also stops probe refresh and buffer uploads while retaining the cached values for later re-enabling. The engine context separately controls whether application debug gizmos are generated and uploaded, allowing large scenes to run without probe, light, and normal overlays. `update_gizmos` uploads world-space debug lines that are depth-tested over the scene. `Mesh` producers use the shared vertex and triangle-index contract; primitive generation is outside the renderer. `Material` currently uses constant base color, metallic, roughness, and emission values; texture-backed properties can be added without changing the mesh contract. `resize` ignores zero dimensions. `render` draws and presents one frame or reports an error.

`GraphicsApi` maps Vulkan, DirectX 12, OpenGL/GLES, and Metal to wgpu backends. Selecting an unavailable API returns an adapter error rather than silently switching APIs.

## Lifecycle

The renderer creates its GPU resources during window resume and drops them on suspension. On resize it reconfigures the surface, recreates the depth target, and updates camera projection. On an outdated surface it reconfigures; on a lost surface it recreates the surface; on timeout or occlusion it skips a frame.

## Verification and open questions

`cargo test --workspace --offline` and `cargo clippy --workspace --all-targets --offline -- -D warnings` passed on Windows. The geometry test checks outward triangle winding. Windowed, borderless, and exclusive-request runs initialized Vulkan and presented a first frame. DirectX 12 also presented a first frame. Pixels, OpenGL, Metal, native exclusive mode, and non-Windows platforms have not been directly inspected in this environment.
